# C05 问题模型、统一符号与伪代码

英文排版源文件为 [c05_model_algorithm.tex](c05_model_algorithm.tex)。它按“问题建模 → 统一符号 → 主算法 → 有限计划构造 → 计划执行”的顺序描述 C05，使用 `algorithm2e` 的 ruled、vlined、linesnumbered 样式。正文采用算法符号，具体实验参数见结果与复现配置。

## 1. 调度问题的实际决策

卫星集合为 $\mathcal S$，天线集合为 $\mathcal A$。每个接触 $v=(s_v,a_v,b_v,e_v)$ 是一个完整、预先确定的可见窗口；其卫星、天线、开始时刻和结束时刻固定。唯一的调度决策是选择或不选择该完整接触，不包含窗口裁剪、可变开始时刻或持续时间优化。

权重为接触时长 $w_v=e_v-b_v$，采用整数时间 ticks。接触按 $(b_v,v)$ 排序；若 $i\prec j$，定义 $\Delta_{ij}=b_j-e_i$。当且仅当以下至少一个条件成立时添加冲突边：

- 同天线：$a_i=a_j$，且 $\Delta_{ij}<\delta^A_{a_i}$。
- 同卫星：$s_i=s_j$，且 $\Delta_{ij}<\delta^S_{s_i}$。

其中 $\delta^A$、$\delta^S$ 是按资源给定的间隔要求。间隔恰好等于某资源阈值时，该资源不引入冲突；另一共享资源仍可引入冲突。

令 $G=(V,E)$，可行调度 $X\subseteq V$ 是该图的独立集。目标为 $F(X)=\sum_{v\in X}w_v$。等价二元模型为最大化 $\sum_v w_vx_v$，满足 $x_i+x_j\leq1$ 对所有冲突边成立，且 $x_v\in\{0,1\}$。

本数据的 `contact_id` 与 `pass_id` 一一对应且唯一。pass 标识作为输入元数据保留，没有增加独立的同 pass 互斥约束，也没有增加站点层面的额外冲突边。八个输入视图共享接触与权重，改变的是天线间隔及其产生的冲突边。

构图规则核对了原始 `scripts/build_graphs.py`、异构天线间隔扩展的 `build_heterogeneous_graphs.py`，以及正式输入导出的 `build_scale_graphs.py`。发布仓库的 NPZ 图及输入哈希提供对应的实例记录；求解器始终以这些原图边和整数权重校验最终结果。

## 2. 图和算法共享的符号

| 符号 | 含义 |
|---|---|
| $\mathcal S$、$\mathcal A$ | 卫星、天线集合 |
| $G=(V,E)$、$X$、$F(X)$ | 冲突图、可行调度、原始整数目标 |
| $\mathcal P=(X_0,\ldots,X_{m-1})$ | 持续存在的搜索种群 |
| $X^*$ | 整次求解保留的历史最优可行调度 |
| $j_{\mathrm{best}}(\mathcal P)$ | 当前种群最优槽位；相等时取最小编号 |
| $\mathcal Z$ | 原生搜索进度记录 |
| $\mathcal H$、$\mathcal H_k$ | 已关闭整段计划记录；本次决策可见的有界近期历史 |
| $o_k$、$\mathcal Q_k$ | 决策快照及与它绑定的有限计划表 |
| $\pi$、$\pi_k$、$\pi_{\mathrm{adapt}}$ | 当前计划、本次选择、初始或回退自适应计划 |
| $\mathcal L_\phi$ | 异步 LLM 计划选择器 |
| $\sigma=(h,\eta,t_h)$ | 当前步骤、是否首次进入、当前步骤计时起点 |
| $J(o_k)$、$R(o_k)$ | 可定向重建的槽位及真实接触锚点 |
| $T$、$\varepsilon$、$d_h$ | 总软时间预算、原生轮次上限、步骤计划持续时间 |

调度统一使用 $X$，不与表示卫星的 $\mathcal S$ 混用。LLM 上送数据统一标为 $(o_k,\mathcal Q_k,\mathcal H_k)$，返回统一标为 $\pi_k$。

## 3. 主算法与异步交互

Algorithm 1 首先载入冲突图、计算可行初解、建立持久种群，并安装默认自适应计划。此后主循环持续推进原生搜索。

在允许的决策机会，主循环生成证据快照 $o_k$、有限计划表 $\mathcal Q_k$ 和近期历史 $\mathcal H_k$，向独立选择层提交异步请求。提交后直接继续搜索，不等待模型返回。模型只能选择已登记的确切计划。

返回的选择通过绑定、身份、字段及新鲜度校验后，主线程才关闭旧计划区间并安装新计划。无效选择保留当前计划。终止时，不再安装未完成的选择，关闭末区间并用原始图与整数权重验证 $X^*$。

流程图应使用两条平行通道：LLM 独立选择在一条通道，持续种群搜索在另一条通道。上送快照和返回计划的箭头是异步消息；主搜索通道不经过等待 LLM 的阻塞节点。

## 4. 有限计划表与执行

Algorithm 2 构造预定义单操作计划，以及绑定“槽位 $j$、真实接触锚点 $r$、资源优先模板 $c$、恢复动作”的组合计划。槽位零和快照中的当前最优槽位不参与定向重建。天线/卫星标识决定模板是否可登记；完整的资源与时间元数据在执行入口再次检查。

Algorithm 3 根据步骤剩余时间执行一个有界原生轮次。定向重建仅在首次进入步骤时尝试一次；进入时重新检查槽位是否已成为当前最优。重建后进行原图可行性和整数目标检查，剩余预算继续原生搜索。计划中的后续恢复动作由登记的 `spread` 或 `merge` 执行。

步骤持续时间结束后转到下一步；若已经是末步，则继续该搜索操作，并保持“不是首次进入”状态，因此不会反复执行重建或扰动入口。若原生操作失败，有后续步骤则前移，否则由主算法安装默认自适应计划。绑定的根节点和槽位不会被静默替换。

## 5. 整段记录及源码对应

每段计划从实际安装时刻开始，到替换、回退安装或终止时关闭。记录包括历史最优值变化、种群目标和变化、实际时长及部分执行状态。符号 $\Delta F_\ell$ 的基准是安装时的历史最优值；文档不将其与经典控制器内部的奖励归一化公式混用。

| Algorithm 2：有限计划登记 | `cipheur_v06/plans.py::build_plans` |
| 定向槽位和阻塞证据 | `cipheur_v06/plan_context.py::augment_packet` |

这些伪代码抽象了网络传输、日志和文件持久化细节，保留快照冻结、异步选择、计划安装、原生推进和整段记录的顺序。LLM 将整段记录作为决策上下文；伪代码不引入模型参数训练。
